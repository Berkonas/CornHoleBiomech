# Sports2D integration contract

Reviewed 7 September 2026 against the official repository and the installed PyPI release. The runtime is **Sports2D 0.8.34**, with **Pose2Sim 0.10.49**. The official repository HEAD inspected was `4392177d75dff43b4da60514d3766029201a5c5e`. No source checkout is bundled and no upstream file is edited. Sports2D is BSD-3-Clause licensed.

Citation: Pagnon, D., & Kim, H. (2024). Sports2D: Compute 2D human pose and angles from a video or a webcam. *Journal of Open Source Software, 9*(101), 6849. <https://doi.org/10.21105/joss.06849>.

Sources: [repository and documentation](https://github.com/davidpagnon/Sports2D), [stable package](https://pypi.org/project/sports2d/0.8.34/), [license](https://github.com/davidpagnon/Sports2D/blob/4392177d75dff43b4da60514d3766029201a5c5e/LICENSE), [public Python entry point](https://github.com/davidpagnon/Sports2D/blob/4392177d75dff43b4da60514d3766029201a5c5e/Sports2D/Sports2D.py).

## What runs

The Mac app invokes the local Python worker through structured JSON messages. `Sports2DAdapter` calls `Sports2D.Sports2D.process(configuration)` directly. It does not launch a Sports2D shell command or scrape log text.

Sports2D owns RTMPose inference, generic person tracking, native angle calculations, diagnostic filtering, TRC/MOT and annotated video. Our layer owns correction records, confidence masking, conservative gap handling after correction, cornhole events, anthropometric normalization, comparisons, outcomes, repeatability and interpretation. Keeping correction-aware filtering here prevents applying a second filter to already filtered inputs.

Native Sports2D outputs are diagnostic outputs under `analyses/<trial>/sports2d/`. Cornhole metrics are calculated from the pre-interpolation tracked pixel arrays, not from Sports2D's filtered TRC. The two output families have separate configurations and angle conventions.

## Raw confidence bridge

Sports2D 0.8.34's public call returns no arrays and its TRC omits per-point confidence. During that public call, a temporary Python return-frame observer copies only the `process_fun` tracked, pre-interpolation coordinate/confidence arrays, names and selected-person identity. It neither changes upstream variables nor modifies source. It is version locked and removed in a `finally` block. Unsupported versions fail explicitly rather than inventing confidence.

These arrays are **Sports2D tracked raw data**, after upstream detection/person rejection, not every detector proposal. Upstream point/average thresholds are set to zero for this capture; our saved `confidence_threshold` (default 0.35) is applied before cornhole measurements. Consequently the native TRC/MOT diagnostic exports may contain samples that the cornhole layer excludes. Always use the cornhole `keypoints.csv`, quality record and plots for the reported metrics. A future upstream confidence-return API should replace this small compatibility bridge.

Sports2D attempts a GUI Matplotlib backend during import and changes the SSL default context. The adapter forces Agg only during import and immediately restores verified TLS; it never disables certificate verification for model downloads. This is necessary for a background native worker, and is covered by the real integration smoke check.

## Capability decisions

| Capability investigated | Application decision |
|---|---|
| RTMPose / RTMLib | First-class backend; body-with-feet, balanced, ONNX Runtime CPU by default |
| Whole body / wrist models | Whole-body option exposed; not used to claim axial wrist rotation |
| Confidence thresholds | Preserve original scores; mask cornhole samples at the configured threshold |
| Sorting / person selection | Sports2D tracking, highest-likelihood track by default; inspect the selected person before interpretation; one visible thrower is the recording protocol |
| Small-gap interpolation | Default maximum 3 frames; retained provenance; long gaps remain missing |
| Butterworth filtering | Native diagnostic exports plus correction-aware cornhole zero-phase SOS filtering; settings recorded separately |
| Alternatives | Native export filter supports the upstream median option through JSON for sensitivity work; cornhole authoritative metrics remain Butterworth or unfiltered |
| Joint and segment angles | Native MOT retained separately; conversion tests for elbow; see METRICS.md |
| Annotated video | Native Sports2D video and correction-aware cornhole video retained |
| Position/angle plots | Focused cornhole figures and interactive native plots; upstream per-landmark plot explosion disabled |
| TRC / MOT | Generated by Sports2D and parsed to verify expected structure |
| C3D | Investigated, intentionally disabled: uncalibrated pixel coordinates must not be labeled millimeters |
| Calibration / floor / camera correction | Disabled in the Stage 1 profile; no participant height or floor is assumed to create metric coordinates |
| Perspective correction | Available upstream but requires defensible camera/scale information; not silently enabled |
| Batch | `cornhole-biomech batch` uses the adapter for each trial; GUI session preserves recording metadata |
| Reload pose | `pose_raw.json` cache supports correction/reanalysis without inference; native Sports2D outputs retain their original configuration/date, and are diagnostic snapshots |
| MPS / Apple Silicon | Investigated upstream MPS/CoreML support. CPU fallback is validated here; GPU selection intentionally rejected pending equivalence/reproducibility tests |
| Pose2Sim / OpenSim | Transitive install dependency only; augmentation and inverse kinematics explicitly disabled |

The presence of a `.trc` or `.mot` does not establish 3D measurement. Do not enable inferred 3D processing merely to obtain another export extension.

## Provenance and failure behavior

Every Sports2D trial records version, inspected source SHA-256, model identity, mode, model and detector hashes, RTMLib/Pose2Sim versions, device, full configuration, cornhole confidence threshold, date and selected-person index. `sports2d_commit` is null for the PyPI install; the documentation separately names the inspected source commit. `manifest.json` includes the source video hash and effective cornhole filter settings.

Missing/unsupported Sports2D or failed inference produces an actionable error. The app never silently substitutes a different model. Users can choose direct RTMPose or MediaPipe in Advanced Analysis. Cached poses and original videos are not removed by a failed analysis. Cancel stops the isolated worker; partially written derived files must be regenerated before interpretation.

## Verification

The release was exercised on a two-second crop of the **official Sports2D demo**, downloaded from the pinned repository commit. This checks actual inference, raw confidence, TRC, MOT, video and cornhole analysis. It is a software integration test, not cornhole validation. The test identified and resolved an upstream Qt initialization crash before successful completion. Unit tests cover missing/version detection, explicit config, independent paths, file readers, missing samples and elbow convention. See QA.md for final run results and limitations.

## Upstream export quirks verified on 0.8.34

The native TRC writer hardcodes `m` in its header even when `to_meters=false` and coordinates remain pixels. The adapter now preserves exact upstream bytes as `.trc.original`, changes only the working export's unit field to `px`, and records both SHA-256 hashes and the repair in `provenance.json`. Zero Z is a file-format placeholder, not measured depth. Never interpret the original `m` label as calibration.

On the 60-frame official demo crop, native TRC and MOT each contained 60 samples, while Sports2D's diagnostic annotation contained 59 frames. The cornhole `annotated.mp4` contained all 60 frames. The app synchronizes against the original copied video and canonical frame indices. Native annotation is retained as a diagnostic artifact.

`scripts/validate_sports2d_exports.py --analysis <directory>` audits readable videos, TRC/MOT structure and both elbow conventions against installed Pose2Sim `fixed_angles` using the same saved raw pixels. The observed maximum conversion discrepancy across 120 elbow samples was 2.85e−14 degrees (floating-point rounding). This is agreement of angle definitions on identical coordinates, **not** pose-estimation accuracy against a human reference.
